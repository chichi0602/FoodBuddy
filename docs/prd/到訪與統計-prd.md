# 到訪與統計 PRD

- 文件狀態：已實作
- 對應階段：Phase 7
- 最後核對日期：2026/10/06

## 一、目標與範圍

Agenda 第 4.3、11、17、18 節：記錄每次實際到訪，讓評分與再訪意願回饋到店家狀態，並從收藏與到訪看出個人口味。

- 範圍：到訪紀錄的新增／編輯／刪除、店家狀態與評分自動同步、時間軸、口味統計、AI 口味分析。
- 非範圍：花費統計、匯出、跨裝置同步。

| 項目 | 內容 |

## 三、到訪紀錄欄位

| 欄位 | 說明 |
|------|------|
| 店家 | 必填；從詳細頁新增時自動帶入，從到訪頁新增時從我的美食選 |
| 到訪日期 | 必填，預設今天，不能選未來 |
| 這次的評分 | 半顆星 |
| 吃了什麼 | 多個，輸入後按 Enter |
| 消費金額 | 新台幣 |
| 同行人 | 自由文字 |
| 心得 | 多行 |
| 願意再來嗎 | 🔁 願意再訪／還不確定（預設）／🚫 不會再去 |
| 照片 | 多張，壓縮成最長邊 1280px |

## 四、自動同步店家

| 動作 | 店家的變化 |
|------|------|
| 新增或編輯到訪 | 加「已去過」、拿掉「想去」 |
| 最新一次選「願意再訪」 | 加「想再訪」 |
| 選「不會再去」 | 存檔後詢問「要把這間店標為不推薦嗎？」；同意 → 加「不推薦」、拿掉「想再訪」 |
| 有評分的到訪 | 店家個人評分 = 所有到訪評分的平均（四捨五入到 0.5） |
| 刪除到訪 | 重新計算平均評分；**不會**拿掉「已去過」 |
| 編輯時換了店家 | 新、舊兩間都重算 |

## 五、時間軸

- 依月份分組（例如「2026 年 10 月 2 次」），新到舊。
- 關鍵字比對店名、吃了什麼、心得、同行人；店家下拉只列有到訪紀錄的店。
- 每筆可編輯、刪除（刪除前確認）；店家名稱連到詳細頁，店家已刪除時顯示「（店家已刪除）」。
- 沒有任何店家時，引導先新增店家（到訪必須掛在店家下）。

## 六、我的統計

| 區塊 | 計算方式 |
|------|------|
| 收藏的店 | 我的美食總數 |
| 去過的店 | 有到訪紀錄或標了「已去過」的店 |
| 到訪次數 | 到訪紀錄總數 |
| 到訪平均評分 | 有評分的到訪平均；沒有時顯示 — |
| 最常收藏的料理 | 不含不推薦的店，前 6 |
| 最常去吃的料理 | 依到訪次數，前 6 |
| 最常去的地區 | 依到訪次數（城市＋行政區），前 5 |
| 評分最高的店 | 不含不推薦的店，前 5，可點到詳細頁 |
| 收藏的價位 | 依價格區間順序 |

圖表為單一色相的水平長條，數值直接標在旁邊；沒有資料時各區顯示說明文字。

## 七、AI 口味分析

- 按「分析我的口味」產生：一段觀察（summary）、3～5 個重點（highlights）、2～3 個「下次可以試試」（suggestions）。
- 送出的資料：口味摘要、統計數字、到訪清單（店名、料理、地區、日期、評分、是否再訪、吃了什麼，最多 100 筆）、不推薦的店名。**不送心得、同行人、金額、照片、備註。**
- AI 不會建議再去不推薦的店，也不推薦具體的新店名（找新店交給 AI 找美食）。
- 結果與分析時間存在瀏覽器，重新整理後仍在；可「重新分析」。沒有任何收藏時按鈕停用。
- 沒有金鑰時顯示示範文字並標註「（示範資料）」。

## 八、與其他功能的關係

- 到訪資料會加進口味摘要（每次到訪 +1、評分 ≥4 再 +1；最新一次「不會再去」視同不喜歡），影響 [AI 找美食](AI找美食-prd.md) 的「根據你的口味推薦」。
