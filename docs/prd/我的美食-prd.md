- 文件狀態：已實作

- 最後核對日期：2026/10/06

## 一、目標與範圍

Agenda 第 4 節：「我的美食」是使用者自己的美食資料庫，可以新增、修改、刪除、收藏、標記想去／去過、評分。

- 範圍：店家 CRUD、多選狀態、個人評分與備註、Tag、圖片、詳細頁、從 AI 推薦加入。
- 非範圍（規劃中）：到訪紀錄（Phase 7）、地圖顯示（Phase 6）、多裝置同步（目前資料只在這個瀏覽器）。

## 二、入口

| 路由 | 頁面 |
|------|------|
| `/my` | [MyFoodPage.tsx](../../client/src/pages/MyFoodPage.tsx) 列表（篩選見 [美食分類與篩選](美食分類與篩選-prd.md)） |
| `/my/new`、`/my/:id/edit` | [PlaceFormPage.tsx](../../client/src/pages/PlaceFormPage.tsx) 新增／編輯 |
| `/my/:id` | [PlaceDetailPage.tsx](../../client/src/pages/PlaceDetailPage.tsx) 詳細頁 |

資料存取一律透過 [placeRepository.ts](../../client/src/db/placeRepository.ts)，資料存在瀏覽器 IndexedDB（見 [資料模型](../architecture/資料模型.md)）。

## 三、店家狀態

| 狀態 | 圖示 | 說明 |
|------|------|------|
| 想去 | 📌 | 新增店家時的預設值 |
| 收藏 | ❤️ | |
| 已去過 | ✅ | |
| 想再訪 | 🔁 | |
| 不推薦 | 🚫 | AI 推薦時會避開這類店與料理 |

**可以複選**，例如「已去過＋想再訪」。列表卡片與詳細頁都能直接切換，不必進編輯頁。

## 四、新增／編輯表單

只有**店家名稱**必填，其他之後都能再補。

| 區塊 | 欄位 |
|------|------|
| 基本資料 | 店家名稱、食物類型（可選預設分類或自行輸入）、店家類型、適合時段（早餐／午餐／下午茶／晚餐／宵夜，可複選）、價格區間（每人）、營業時間、電話、推薦餐點 |
| 位置 | 地址、國家（預設台灣）、城市、地區、Google Maps 位置、緯度、經度 |
| 圖片與連結 | 圖片（可多張，自動壓縮成最長邊 1280px 的 JPEG）、網路連結 |
| 我的紀錄 | 狀態（可複選）、個人評分（半顆星）、Tag（會提示已有的 Tag）、個人備註 |

- 貼上完整的 Google Maps 網址、離開欄位時，若經緯度尚未填寫，會自動帶入（支援 `@lat,lng` 與 `?q=lat,lng`）；`maps.app.goo.gl` 短網址無法解析。
- 預設料理分類：日式、韓式、台式、中式、西式、義式、燒肉、火鍋、拉麵、牛排、咖啡、甜點、飲料、小吃（Agenda 第 5 節）。

## 五、詳細頁

- 標題、地區／店家類型、「在 Google Maps 開啟」（有網址用網址，否則用座標或地址搜尋）、編輯、刪除（確認後刪除，到訪紀錄一併刪除）。
- 圖片可點開預覽。
- **我的紀錄**：狀態切換、評分、備註、Tag。
- **基本資料**：地址、食物類型、適合時段、價格、營業時間、電話（可點撥）、推薦餐點、經緯度、網路連結。
- **AI 整理**：從 AI 找美食加入的店，會保存當時的推薦原因、網路評價、推薦族群、優缺點，並註明是哪天、搜尋什麼時由 AI 整理。手動新增的店顯示空狀態與「AI 找美食」連結。

## 六、從 AI 推薦加入

AI 找美食的推薦卡片可一鍵「加入想去／加入收藏／標記去過」，會建立 `source: 'ai'` 的店家，並寫入：

- OpenStreetMap 的店名、座標、地址、營業時間、電話、官方網站
- AI 整理的料理類型、店家類型、價格區間、推薦餐點與分析（`aiSummary`）
- Google Maps 連結（有地址用「店名＋地址」，沒有就用座標）

適合時段不會自動填，需要的話在編輯頁補上。

## 七、規劃中

- Phase 6：在地圖上用不同標記顯示收藏、想去、去過。
- Phase 7：到訪紀錄（日期、評分、推薦餐點、消費金額、同行人、照片、心得、是否願意再訪）。
