## 一、目標與範圍

Agenda 第 5 節：依地理、美食、用餐情境、價格、個人狀態篩選自己的資料，並可用 Tag 擴充分類。

## 三、列表工具列

- 狀態分頁：全部／想去／收藏／已去過／想再訪／不推薦（各自顯示數量）。
- 關鍵字：比對店名、地址、國家、城市、地區、店家類型、備註、料理、Tag、推薦餐點。
- 「篩選」按鈕：右上角顯示已套用的條件數。電腦版在列表上方展開面板，手機版從下方滑出，底部有「清除條件」與「顯示 N 間」。
- 排序：最近更新（預設）、個人評分高到低、店名、價格低到高、價格高到低、距離近到遠。**缺少排序依據的店一律排在最後。**
- 列表上方顯示「共 N 間」與已套用條件標籤，可逐一移除或「清除全部條件」。

## 四、篩選條件

| 類別 | 選項 | 規則 |
|------|------|------|
| 地區 | 國家、城市、行政區（多選下拉，選項取自現有資料） | 選了國家／城市後，下一層只列相符的選項 |
| 附近 | 開關＋1／3／5／10 公里 | 需要瀏覽器定位；只顯示有經緯度、且在範圍內的店；卡片顯示距離 |
| 料理 | 預設 14 類＋資料中自訂的料理 | |
| 用餐情境 | 早餐、午餐、下午茶、晚餐、宵夜 | 對應店家的「適合時段」 |
| 價格 | $200 以下、$200～500、$500～1000、$1000 以上＋自訂每人預算 | 預算落在哪個區間就符合（500 同時符合兩個相鄰區間）；沒填價格的店不符合預算條件 |
| 我的狀態 | 五種狀態＋「未去過」 | 「未去過」＝沒有「已去過」狀態，和其他狀態屬同一類 |
| Tag | 所有 Tag | |

**同一類多選是「或」，不同類之間是「且」。**例如選「小吃」「燒肉」＝兩種都會出現；再加「高雄市」＝只剩高雄的。

所有條件都記在網址上（例如 `/my?city=高雄市&cuisine=日式&km=3&sort=distance`），重新整理或分享連結都會保留。

## 五、定位

- 開啟「附近」或選擇「距離近到遠」時才要求定位。
- 定位失敗時顯示原因（沒有權限、無法取得、逾時），不會自動重試；關掉「附近」再打開才會重新嘗試。
- 還沒拿到位置前不套用距離條件，避免列表瞬間變空。

## 六、Tag 管理（設定頁）

- 列出所有 Tag 與使用的店家數（點 Tag 會跳到篩選該 Tag 的列表）。
- **重新命名**：改成已存在的名字會合併成同一個 Tag，對話框會先提示。
- **刪除**：從所有店家移除這個 Tag，店家本身不會被刪除。
