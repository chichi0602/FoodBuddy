# 帳號與同步 PRD

- 文件狀態：已實作
- 對應階段：Phase 9
- 最後核對日期：2026/10/22

## 一、目標與範圍

FoodBuddy 公開給任何人免費使用。每個人自己註冊帳號，資料存在伺服器，換手機或電腦登入都看得到；斷線時仍可使用。

- 範圍：註冊、登入（Email＋密碼、Google）、登出、刪除帳號、雲端同步、舊資料搬家、AI 與地圖功能需登入。
- 非範圍（規劃中）：忘記密碼（需寄信服務）、驗證信箱、修改 Email 或密碼、AI 每日額度與限流（Phase 10）。

## 二、入口

| 項目 | 內容 |
|------|------|
| 路由 | `/login`、`/register`；未登入時任何頁面都導到 `/login?next=原頁面` |
| 設定頁 | `/settings` 最上方「帳號」區塊 |
| 前端 | [AuthPage.tsx](../../client/src/pages/AuthPage.tsx)、[AuthProvider.tsx](../../client/src/auth/AuthProvider.tsx)、[LegacyImportPrompt.tsx](../../client/src/auth/LegacyImportPrompt.tsx)、[AccountCard.tsx](../../client/src/components/AccountCard.tsx)、[syncEngine.ts](../../client/src/sync/syncEngine.ts)、[db.ts](../../client/src/db/db.ts) |
| API | `/api/auth/*`、`POST /api/sync`（見 [Web API 端點目錄](../architecture/Web%20API%20端點目錄.md)） |
| 後端 | `AuthController`、`SyncController`、`AppDbContext`（SQLite） |

## 三、註冊與登入

| 規則 | 內容 |
|------|------|
| 註冊欄位 | 暱稱（選填，30 字內）、Email、密碼、再輸入一次密碼 |
| 密碼 | 至少 8 個字元，不強制大小寫或符號 |
| Email | 不可重複；重複時提示「已經註冊過了，請直接登入」 |
| 登入失敗 | 一律顯示「Email 或密碼不正確」；連續 5 次鎖 15 分鐘 |
| 用 Google 註冊的帳號用密碼登入 | 提示改按「用 Google 登入」 |
| Google 登入 | 後端有設定 Google 用戶端才顯示按鈕。第一次用 Google 登入會自動建立帳號；同一個 Email 已有帳號時會自動連結 |
| 登入狀態 | HttpOnly Cookie，30 天內有使用就自動延長 |
| 登入後 | 回到 `next` 指定的頁面（只接受站內路徑），否則回首頁 |

## 四、資料同步

- 畫面讀寫的是瀏覽器裡**這個帳號自己的資料庫**（`foodbuddy-{帳號 id}`），伺服器存正本。
- 什麼時候同步：修改後約 2 秒、切回 FoodBuddy 視窗、網路恢復、每 5 分鐘、設定頁按「立即同步」。
- **新裝置第一次登入**：顯示「正在下載你的資料…」，下載完才進主畫面。
- **離線**：連不上伺服器時，用上次登入的帳號開啟本機資料，可以照常瀏覽與修改，連線後自動上傳。
- **衝突**：同一筆資料在兩台裝置都改過時，以較晚修改的為準（整筆）。
- **同步的資料**：店家、個人狀態與評分、到訪紀錄（含照片）、Tag、AI 搜尋紀錄、沒興趣清單。
- **不同步的資料**：首頁上次的推薦結果、AI 口味分析結果（只存在這台裝置，重新產生即可）。

| 限制 | 數值 |
|------|------|
| 每個帳號資料筆數 | 20000 筆 |
| 單筆資料 | 4MB（照片太多的到訪紀錄會被拒絕） |

## 五、設定頁「帳號」

| 項目 | 內容 |
|------|------|
| 帳號資訊 | 暱稱（沒有時顯示 Email）、Email、登入方式 |
| 同步狀態 | 同步中／已同步（時間）／N 筆修改等待上傳／離線中／錯誤訊息 |
| 立即同步 | 手動同步一次 |
| 登出 | 先同步。還有沒上傳的修改時警告「現在登出的話，這些修改會遺失」。登出後刪除這台裝置上的帳號資料，回到 `/login` |
| 刪除帳號 | 輸入「刪除」才能按「永久刪除」。伺服器上的帳號與所有資料一併刪除，無法復原 |

## 六、登入前的舊資料

Phase 8 以前的資料存在瀏覽器的 `foodbuddy` 資料庫。登入後如果這台瀏覽器有這個資料庫且裡面有資料：

- 跳出「把這台裝置上的資料加入帳號？」，顯示店家與到訪紀錄的數量
- **加入帳號**：全部加入目前帳號並上傳，然後刪除舊資料庫
- **先不要**：資料留在裝置上，這個帳號之後不再詢問
- 舊資料庫是空的就直接刪除，不詢問

## 七、需要登入的功能

AI 找美食、為你推薦、口味分析、用地址找座標都需要登入；未登入呼叫回 401。
任何 API 回 401 時（例如登入過期），畫面回到登入頁並提示「登入已過期」，本機資料保留。
