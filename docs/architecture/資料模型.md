# 資料模型

- 文件狀態：維護中
- 對應階段：Phase 8
- 最後核對日期：2026/10/07

所有使用者資料存在瀏覽器 IndexedDB，資料庫名稱 `foodbuddy`，以 Dexie 操作。
定義在 [db/db.ts](../../client/src/db/db.ts)，型別在 [types/index.ts](../../client/src/types/index.ts)。

## 一、資料表

| 資料表 | 主鍵 | 索引 | 說明 | 使用中 |
|--------|------|------|------|------|
| `places` | `id`（UUID） | name、city、district、priceRange、*cuisines、*mealTimes、*tags、updatedAt | 店家基本資料 | ✅ |
| `userPlaces` | `placeId` | *statuses、rating | 使用者對店家的狀態、評分、備註 | ✅ |
| `tags` | `name` | | 已使用過的 Tag（輸入提示與管理） | ✅ |
| `searchHistory` | `id` | createdAt | AI 搜尋歷史 | ✅ |
| `visits` | `id` | placeId、visitedAt | 到訪紀錄 | ✅（Phase 7 起使用；刪店家時一併刪除） |
| `dismissed` | `id`（OSM id） | dismissedAt | 按過「沒興趣」的推薦店家（name、dismissedAt） | ✅（Phase 8，v3） |

`*` 表示多值索引（陣列）。

把「店家」與「我對這間店的看法」分成 `places` 與 `userPlaces` 兩張表，對應 Agenda 第 19 節的 Place／UserPlace。列表顯示時合併成 `PlaceWithUser`。

## 二、主要型別

### Place

| 欄位 | 型別 | 說明 |
|------|------|------|
| id | string | UUID |
| name | string | 必填 |
| address、country、city、district | string? | |
| googleMapsUrl | string? | |
| lat、lng | number? | 有值才算得出距離、才能用座標比對收藏 |
| cuisines | string[] | 料理類型 |
| mealTimes | MealTime[] | 適合時段（Phase 2 新增） |
| placeType | string? | 店家類型 |
| priceRange | `under200`／`200to500`／`500to1000`／`over1000` | 每人價格區間 |
| openingHours、phone | string? | |
| recommendedDishes、images、links、tags | string[] | images 為壓縮後的 data URL |
| source | `manual`／`ai` | 手動新增或從 AI 推薦加入 |
| aiSummary | AiSummary? | 從 AI 加入時的分析（Phase 3 新增） |
| createdAt、updatedAt | number | 毫秒時間戳 |

### UserPlace

| 欄位 | 型別 | 說明 |
|------|------|------|
| placeId | string | 對應 Place.id |
| statuses | PlaceStatus[] | `wantToGo`、`favorite`、`visited`、`revisit`、`notRecommended`，可複選 |
| rating | number? | 0.5～5 |
| note | string? | 個人備註（**不會送給 AI**） |
| updatedAt | number | |

### VisitRecord（Phase 7 起使用）

| 欄位 | 型別 | 說明 |
|------|------|------|
| id | string | UUID |
| placeId | string | 對應 Place.id |
| visitedAt | string | `YYYY-MM-DD` |
| rating | number? | 這次的評分 |
| dishes | string[] | 吃了什麼 |
| spending | number? | 消費金額（新台幣） |
| companions | string? | 同行人（不送給 AI） |
| photos | string[] | 壓縮後的 data URL（不送給 AI） |
| review | string? | 心得（不送給 AI） |
| wouldRevisit | boolean? | true 願意再訪、false 不會再去、undefined 還不確定 |
| createdAt | number | |

寫入到訪時會同步 `userPlaces` 的狀態與評分，規則見 [到訪與統計 PRD 第四節](../prd/到訪與統計-prd.md)。

### AiSummary

reason、pros[]、cons[]、reputation?、suitableFor?、query（當時的搜尋）、savedAt。

## 三、版本與升級

| Dexie 版本 | 變更 | 升級處理 |
|------|------|------|
| 1 | 初始五張表 | — |
| 2 | `places` 新增 `*mealTimes` 索引 | 舊資料補 `mealTimes: []` |
| 3 | 新增 `dismissed` 資料表 | 不需轉換 |

新增版本時用 `db.version(N).stores({...}).upgrade(...)`，不要修改舊版本的定義。

## 四、資料存取

所有頁面只透過 repository 讀寫，不直接操作 `db`（Tag 輸入提示與搜尋歷史的唯讀查詢除外）：

- [placeRepository.ts](../../client/src/db/placeRepository.ts)：list、get、create、update、remove、toggleStatus、setRating、setLocation（補座標，不更新 updatedAt）
- [tagRepository.ts](../../client/src/db/tagRepository.ts)：listWithCount、rename（同名合併）、remove
- [visitRepository.ts](../../client/src/db/visitRepository.ts)：listWithPlace、listByPlace、create、update、remove、markNotRecommended（寫入後同步店家狀態與評分）

- [dismissedRepository.ts](../../client/src/db/dismissedRepository.ts)：list、ids、add、remove

AI 口味分析的結果（`foodbuddy.tasteInsight`）與首頁為你推薦的結果（`foodbuddy.forYou`）存在 localStorage，不在 IndexedDB。
