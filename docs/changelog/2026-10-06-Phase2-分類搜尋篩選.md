## 功能介紹

- **篩選條件**：國家／城市／行政區（選了城市，行政區只列該城市的）、附近、料理、用餐情境、價格區間＋自訂每人預算、我的狀態（含「未去過」）、Tag。
- **自訂預算**：落在哪個價格區間就符合，例如 500 會同時符合「$200～500」與「$500～1000」。
- **條件記在網址**：重新整理不會遺失，首頁的狀態數字連結（`/my?status=…`）也照常運作。
- **已套用條件**可一個個移除，或「清除全部條件」。
- **Tag 管理**：列出每個 Tag 用在幾間店；改成已存在的名字會**合併**；刪除只從店家移除 Tag，不刪店家。

## ⚠️ 踩到的問題與修正

- **定位失敗會無限重試**：effect 依賴 `locating`，失敗後 `locating` 變回 false 又觸發定位。改成失敗時保留錯誤、不自動重試；關掉「附近」才清除錯誤，下次開啟再試。
- **還沒拿到位置前套用距離條件會讓列表瞬間變空**：位置未取得時先忽略距離條件。
- **選取的篩選標籤變成空白框**：自訂的白底樣式蓋掉 antd 的選取色，改成選取時深 teal 底白字。
- antd 會在兩個中文字的按鈕中間自動加空白（「合 併」），自動化測試的按鈕名稱要用 `/合.?併/` 這種寫法比對。

## 刻意的取捨

- 「未去過」和其他狀態歸在同一類（或的關係），因為使用者會想看「想去 或 未去過」。
- 只有填了經緯度的店才算得出距離；開啟「附近」時沒有座標的店不會出現。

## 驗證

用 Playwright 直接建立一份 **v1 結構的舊資料庫**（其中一間店沒有 `mealTimes`）測試升級，再逐項比對篩選結果，**20 項全部通過**：

- 城市、料理（或）、城市＋時段（且）、晚餐、預算 300、預算 500（邊界）、價格多選、未去過、已去過、Tag、關鍵字
- 1 公里內、10 公里內＋距離排序（用 Playwright 模擬定位）、價格排序、評分排序
- UI 點選篩選、Tag 合併後筆數、Tag 刪除、編輯後「下午茶」可被篩到
