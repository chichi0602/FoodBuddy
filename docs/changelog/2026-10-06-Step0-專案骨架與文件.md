## 變更目的

使用者帶著一份與 AI 討論出的需求 PDF（個人美食收藏 + AI 美食探索 ver2）來，要求：

1. 依文件的步驟一步一步實作
2. 建立 `docs/` 存放這份文件
3. 用 React 製作，元件參考 Ant Design
4. 畫面使用使用者提供的五色配色

開工時 repo 是空的（只有 `.git`，main 分支沒有任何 commit）。

## 與使用者確認的決策

開始前用三輪問答確認了會影響整體架構的事：

| 問題 | 使用者的選擇 | 影響 |
|------|------|------|
| 資料存哪裡 | 先存瀏覽器 | 用 IndexedDB，不需要資料庫與登入 |
| AI 服務 | Azure OpenAI，金鑰之後提供 | 先做 Mock，拿到金鑰再串 |
| 金鑰怎麼用 | 「開一個管理金鑰，然後 appsetting 讀取」→ 確認為 ASP.NET Core 後端代理 | 新增 `server/` 後端，前端不接觸金鑰 |
| 是否用 Azure Key Vault | 不用，放 appsettings 即可 | 之後改成 User Secrets，見 [金鑰改用 UserSecrets](2026-10-06-金鑰改用UserSecrets.md) |
| 後端存資料嗎 | 維持存瀏覽器 | 後端只當 AI 代理 |
| 地圖 | Leaflet + OpenStreetMap | 免費免金鑰 |
| App 形式 | 響應式 Web App | 不做 React Native |
| Git | 分階段做，使用者確認後才 commit | 每個 Phase 結束都停下等驗收 |

## 怎麼生成

1. **需求文件**：把 PDF 內容轉成 Markdown，存為 `docs/food-ai-system.md`（後來搬到 [planning/](../planning/AI美食紀錄與探索系統-需求Agenda.md)）。表格化了第 6 節「解析條件」與第 10、19 節。
2. **前端**：`npm create vite@latest client -- --template react-ts`，再安裝
   `antd @ant-design/icons react-router-dom dexie dexie-react-hooks leaflet react-leaflet dayjs`。
   ⚠️ 計畫寫的是 antd v5，實際裝到的是 **v6**（當時最新），ConfigProvider 主題寫法相同。
3. **後端**：`dotnet new webapi -n FoodBuddy.Api -f net8.0 --use-controllers`（機器上有 .NET 8 與 10，選 LTS 的 8）。刪掉範本的 WeatherForecast，加上 CORS 與 `GET /api/health`。
4. **開發代理**：[vite.config.ts](../../client/vite.config.ts) 把 `/api` 轉到 `http://localhost:5122`，前端不需處理跨網域。
5. **`.gitignore`**：排除 `node_modules`、`bin/obj`、放金鑰的 `appsettings.Development.json`。
6. **主題與版面**：[theme.ts](../../client/src/theme/theme.ts)（antd token）、[AppLayout.tsx](../../client/src/layout/AppLayout.tsx)（電腦版左側選單、手機版底部分頁列）。
7. **README**：寫上啟動方式與 Azure OpenAI 設定位置。

## 功能介紹

- 首頁的主角是「今天想吃什麼？」對話式輸入框（AI 找美食入口），下方是「我的美食」各狀態數量與最近更新。
- 選單：首頁、AI 找美食、我的美食、地圖、到訪紀錄、設定。尚未完成的頁面顯示「這個功能會在 Phase N 完成」。
