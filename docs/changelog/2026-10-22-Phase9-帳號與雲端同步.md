# Phase 9：帳號與雲端同步

- 文件狀態：已實作
- 對應階段：Phase 9
- 最後核對日期：2026/10/22

## 變更目的

使用者要把 FoodBuddy 放到自己／公司的 IIS 主機，**公開給任何人免費使用，每個人自己註冊帳號**。
在這之前，資料只存在瀏覽器 IndexedDB、沒有帳號，所以：

- 換手機、換電腦就看不到資料
- 清除瀏覽器資料就全部消失
- 任何人都能直接呼叫後端 AI，花 Azure 的費用

上站準備分成兩個階段：**Phase 9 帳號與雲端同步**（這篇）、Phase 10 安全、IIS 部署、載入速度與 PWA。

## 與使用者確認的決策

| 問題 | 使用者的選擇 |
|------|------|
| 測試站放哪裡 | 公司／自己的 **IIS 主機** |
| 誰會使用 | **公開給任何人**，每個人**自己註冊**，免費使用 |
| 登入方式 | **Email＋密碼**，另外也能用 **Google 登入** |
| 資料庫 | **SQLite** |
| AI 額度 | 每人每天 20 次（Phase 10 實作） |
| 地圖圖磚 | 先維持 OSM 圖磚（Phase 10 文件註明限制） |
| AI 加速的改動 | 先 commit push，再開始 Phase 9 |

## 怎麼生成

### 整體作法：本機資料庫＋背景同步

畫面有 48 處直接用 `useLiveQuery` 讀 Dexie。如果改成每次都打 API，幾乎每一頁都要重寫，而且斷網就不能用。
所以**畫面繼續讀寫瀏覽器裡的 Dexie**，伺服器當正本，兩邊在背景同步：

```
畫面 ──讀寫──► Dexie（每個帳號一個資料庫 foodbuddy-{userId}）
                 │  每筆寫入同時記到 outbox（同一個交易）
                 ▼
            syncEngine ──POST /api/sync { since, changes }──► 後端 SyncRecords（SQLite）
                 ▲                                              │
                 └──────── 其他裝置的變更、新的 cursor ◄─────────┘
```

### 後端

- 套件：`Microsoft.AspNetCore.Identity.EntityFrameworkCore`、`Microsoft.EntityFrameworkCore.Sqlite`、`Microsoft.EntityFrameworkCore.Design`、`Microsoft.AspNetCore.Authentication.Google`，全部固定 8.0.32。
- [Data/AppDbContext.cs](../../server/FoodBuddy.Api/Data/AppDbContext.cs)：
  - `AppUser`：Identity 使用者，加上暱稱 `DisplayName` 與建立時間
  - `SyncRecord`：一筆前端資料在伺服器的正本，整筆存 JSON。前端資料欄位之後怎麼改，後端都不用跟著改。
  - 唯一索引 (UserId, Collection, RecordId)；刪除帳號時以外鍵一併刪除
- [Data/Migrations](../../server/FoodBuddy.Api/Data/Migrations/)：`Initial` migration，後端啟動時自動 `Migrate()`。
- [Program.cs](../../server/FoodBuddy.Api/Program.cs)：
  - **資料庫路徑**：`Database:Path`，預設 `App_Data/foodbuddy.db`。相對路徑以網站資料夾為準，不受 IIS 工作目錄影響。
  - **Identity**：Email 不可重複；密碼至少 8 碼，不強制大小寫或符號；登入失敗 5 次鎖 15 分鐘。
  - **Cookie 驗證**：`FoodBuddy.Auth`，HttpOnly、SameSite=Lax，30 天滑動到期。API 未登入回 401，不轉址。
  - **Google**：`Authentication:Google:ClientId／ClientSecret` 都有填才啟用。
- [Services/Auth/ChineseIdentityErrorDescriber.cs](../../server/FoodBuddy.Api/Services/Auth/ChineseIdentityErrorDescriber.cs)：註冊錯誤訊息改為繁體中文。
- [Controllers/AuthController.cs](../../server/FoodBuddy.Api/Controllers/AuthController.cs)：`providers`、`register`、`login`、`logout`、`me`、`DELETE account`、`google`、`google/callback`。
- [Controllers/SyncController.cs](../../server/FoodBuddy.Api/Controllers/SyncController.cs)：`POST /api/sync`。
  - 只接受 6 種資料：places、userPlaces、visits、tags、searchHistory、dismissed。
  - 每次最多 500 筆；單筆最多 4MB；請求最多 20MB；每個帳號最多 20000 筆。
  - **衝突處理**：以前端修改時間較新的為準。較舊的修改不會覆蓋，伺服器會把較新的版本傳回去。
  - 刪除保留「墓碑」（Deleted=true），其他裝置才知道要刪除。
  - 一次最多回傳 300 筆，`hasMore` 表示還有下一頁。
- `AiController`、`GeoController` 加上 `[Authorize]`：沒登入不能用 AI 和找座標。

### 前端

- [db/db.ts](../../client/src/db/db.ts)：
  - **每個帳號一個資料庫** `foodbuddy-{userId}`，以 live binding 匯出 `db`。原本 import `db` 的 48 個地方都不用改。
  - v4 新增 `outbox`（待上傳）與 `meta`（同步 cursor、上次同步時間）。
  - **Dexie DBCore middleware**：
    - 每個讀寫交易自動加入 outbox。
    - 每筆新增、修改、刪除都在同一個交易裡記下「哪一筆變了」。
    - repository 和頁面裡直接寫 db 的地方都不用改。
    - outbox 只記 collection＋id＋時間，上傳時再讀當下內容：讀不到代表已刪除。
  - 從伺服器拉下來的資料用標記過的交易寫入，不會再記進 outbox。
- [sync/syncEngine.ts](../../client/src/sync/syncEngine.ts)：
  - 什麼時候同步：寫入後 2 秒、回到前景、重新連線、每 5 分鐘、手動按「立即同步」。
  - 一次最多上傳 200 筆／約 4MB，有 hasMore 就繼續拉。
  - 本機還有沒上傳的修改時，不會被伺服器的資料蓋掉。
- [auth/AuthProvider.tsx](../../client/src/auth/AuthProvider.tsx)、[auth/authContext.ts](../../client/src/auth/authContext.ts)：
  - **登入狀態**：啟動時問 `/api/auth/me`。
  - **離線**：連不上伺服器時，用上次登入的帳號開啟本機資料。
  - **新裝置**：第一次登入時先顯示「正在下載你的資料…」，下載完才進主畫面。
  - **登入過期**：任何 API 回 401 就回到登入頁。本機資料保留，因為可能還有沒上傳的修改。
  - **登出／刪除帳號**：刪除這台裝置上的帳號資料庫，並清除 localStorage 裡的推薦與口味分析快取。
- [pages/AuthPage.tsx](../../client/src/pages/AuthPage.tsx)：登入、註冊共用一頁。
  - 有 Google 才顯示「用 Google 登入」。
  - 登入後回到原本要去的頁面（`?next=`，只接受站內路徑）。
- [auth/LegacyImportPrompt.tsx](../../client/src/auth/LegacyImportPrompt.tsx)：瀏覽器裡有登入前的 `foodbuddy` 資料庫時，詢問「把這台裝置上的資料加入帳號？」，並顯示店家數與到訪筆數。
  - **加入帳號**：整批寫進帳號資料庫並上傳，然後刪除舊資料庫。
  - **先不要**：資料留在裝置上，這個帳號之後不會再被詢問。
- [components/AccountCard.tsx](../../client/src/components/AccountCard.tsx)：設定頁的「帳號」區塊。
  - 顯示暱稱、Email、登入方式、同步狀態。
  - **立即同步**。
  - **登出**：還有沒上傳的修改時會先警告。
  - **刪除帳號**：要輸入「刪除」才能按。
- [services/http.ts](../../client/src/services/http.ts)：共用的 `requestJson`。統一處理錯誤訊息，並在 401 時通知回到登入頁。`aiApi`、`geoApi` 改用它。
- [vite.config.ts](../../client/vite.config.ts)：開發時 `/signin-google` 也轉給後端（Google 登入回呼）。
- `.gitignore`：加入 `server/FoodBuddy.Api/App_Data/`。

## 功能介紹

- 第一次打開網站會看到登入頁，可以用 Email 免費註冊，或用 Google 登入。
- 登入後和以前一樣使用，資料會自動備份到伺服器。換手機或電腦登入，資料會跟著過去。
- 斷線時還能看、能改，連上網路後自動補上傳。
- 以前沒有帳號時存的資料，第一次登入時可以選擇加入帳號。
- 設定頁可以看同步狀態、登出、刪除帳號。

## ⚠️ 踩到的問題與修正

| 問題 | 原因 | 修正 |
|------|------|------|
| 較舊的修改被伺服器拒絕後，送出的裝置一直保留舊資料 | 伺服器的較新版本小於這台裝置的 cursor，不會出現在回傳裡 | 被拒絕的資料不論版本，一律傳回給送出的裝置 |
| 中文資料送進同步 API 回 500 | 用 Git Bash 的 curl 測試時送出非 UTF-8 文字（測試工具問題），但伺服器不該因此 500 | 無法轉成 UTF-8 的內容回 400 |
| 在其他裝置刪除帳號後，這台裝置的 Cookie 還沒過期，同步時會寫入不存在的使用者 | Cookie 預設 30 分鐘才重新驗證一次 | 同步前確認帳號還存在，不存在回 401 |
| 從設定頁登出後，再登入會回到設定頁 | 登出時狀態先變成未登入，路由把目前頁面記成 `?next=/settings` | 登出時把「切換狀態」和「換到 /login」放在同一次更新 |
| React 警告 key 重複、在 render 中更新其他元件 | 兩個並列元件用了相同 key；在 setState 的 updater 裡顯示訊息 | 改用一個有 key 的 Fragment 包住；目前狀態改用 ref 讀取 |
| EF Core 把每一句 SQL 都寫進 log | 預設 Information | `appsettings.json` 把 `Microsoft.EntityFrameworkCore` 設為 Warning |

## 刻意的取捨與已知限制

- **衝突處理是「最後寫入的贏」，以整筆資料為單位**：兩台裝置同時改同一間店的不同欄位，較晚的會整筆覆蓋。個人資料很少同時在兩台裝置編輯，所以先不做欄位層級合併。
- **忘記密碼**：要寄信，這次還沒接寄信服務。用 Google 登入的人不受影響。
- **沒有驗證信箱**：為了防止有人先用別人的 Email 註冊，Google 登入遇到「同 Email、沒驗證過」的帳號時，會移除原本的密碼並接管帳號，由真正擁有信箱的人取得控制權。
- **登出會刪除本機資料**：公用電腦比較安全。下次登入會從伺服器重新下載。
- **照片**：照片仍是壓縮後的 data URL，跟著到訪紀錄存成 JSON。單筆上限 4MB。
- **Data Protection 金鑰**：開發環境用預設位置。部署到 IIS 時要固定存放位置，否則應用程式集區回收後所有人都要重新登入（Phase 10 處理）。
- 限流、AI 每日額度、IIS 部署：Phase 10。
