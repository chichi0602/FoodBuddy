## 一、Azure OpenAI 金鑰（.NET User Secrets）

金鑰放在**使用者資料夾**的 secrets.json，不在專案資料夾內，不會被推上 git。後端在 Development 環境啟動時自動讀取，優先於 appsettings。

**檔案位置**

```
%APPDATA%\Microsoft\UserSecrets\61fdfd9c-d88f-4efe-b8f9-20e5fd73fb71\secrets.json
```

（`61fdfd9c-…` 是 [FoodBuddy.Api.csproj](../../server/FoodBuddy.Api/FoodBuddy.Api.csproj) 裡的 `UserSecretsId`，只是資料夾編號，不是秘密。）

**方法一：直接編輯**

```json
{
  "AzureOpenAI": {
    "Endpoint": "https://<資源名稱>.openai.azure.com/",
    "ApiKey": "<金鑰>",
    "Deployment": "<部署名稱，例如 gpt-5>"
  }
}
```

**方法二：指令**

```bash
cd server/FoodBuddy.Api
dotnet user-secrets set "AzureOpenAI:Endpoint" "https://<資源名稱>.openai.azure.com/"
dotnet user-secrets set "AzureOpenAI:ApiKey" "<金鑰>"
dotnet user-secrets set "AzureOpenAI:Deployment" "<部署名稱>"
dotnet user-secrets list
```

設定後**重開後端**，打開 http://localhost:5122/api/health，`aiConfigured: true` 代表三個值都讀到了。
三個值任一沒填，後端會改用示範模式（MockAiService）。

## 二、appsettings.json

[appsettings.json](../../server/FoodBuddy.Api/appsettings.json) 進版控，**不放任何金鑰**。

| 區塊 | 欄位 | 說明 |
|------|------|------|
| `Database` | `Path` | SQLite 資料庫檔案，預設 `App_Data/foodbuddy.db`；相對路徑以後端（網站）資料夾為準 |
| `Authentication:Google` | `ClientId`、`ClientSecret` | Google 登入用；**兩個都填才會啟用**，ClientSecret 放 User Secrets |
| `Cors` | `AllowedOrigins` | 允許的前端來源，預設 `http://localhost:5173`（開發時走 Vite 代理，其實用不到） |
| `AzureOpenAI` | `Endpoint`、`ApiKey`、`Deployment` | 留空，實際值放 User Secrets |
| | `ApiVersion` | `v1`（預設）使用新版 `/openai/v1/chat/completions`；填其他值（例如 `2025-04-01-preview`）改走舊版 deployments 路徑 |
| `Osm` | `UserAgent` | 呼叫 Nominatim／Overpass 時的 User-Agent（Nominatim 使用政策要求可辨識） |
| | `NominatimUrl` | 地名轉座標服務 |
| | `OverpassUrls` | 店家查詢服務，依序嘗試（主站、備援站） |

`appsettings.Development.json` 只有 Logging 設定，已列入 `.gitignore`。
`Logging:LogLevel:Microsoft.EntityFrameworkCore` 設為 Warning，避免每一句 SQL 都寫進 log。

### Google 登入（選填）

1. 到 Google Cloud Console → API 和服務 → 憑證，建立「OAuth 用戶端 ID」，類型選「網頁應用程式」。
2. 「已授權的重新導向 URI」加入 `http://localhost:5173/signin-google`（開發）與 `https://<正式網域>/signin-google`（正式）。
3. 把用戶端 ID 與密鑰放進 User Secrets：

```bash
cd server/FoodBuddy.Api
dotnet user-secrets set "Authentication:Google:ClientId" "<用戶端 ID>"
dotnet user-secrets set "Authentication:Google:ClientSecret" "<用戶端密鑰>"
```

4. 重開後端。登入頁出現「用 Google 登入」按鈕，就代表已經啟用。

## 四、模型參數（寫在程式裡）

[AzureOpenAiService.cs](../../server/FoodBuddy.Api/Services/AzureOpenAiService.cs)：

| 呼叫 | reasoning_effort | max_completion_tokens |
|------|------|------|
| 解析需求 | minimal | 2000 |
| 挑選與分析 | minimal | 4000 |

部署不接受某個 `reasoning_effort` 值時，依序改試 `minimal` → `none` → `low`，都不行才拿掉參數；每個部署成功的值會記住（例如 `gpt-5.6-sol` 不接受 minimal，實際用 none）。HTTP 逾時 90 秒。

## 五、各工作使用不同部署（選填）

同一個 Azure 資源可以部署多個模型。以下欄位放在 `AzureOpenAI` 區塊（部署名稱不是秘密，可放 appsettings.json 或 secrets.json）：

| 欄位 | 說明 |
|------|------|
| `ParseDeployment` | 解析需求用的部署，沒填用 `Deployment` |
| `RankDeployment` | 挑選與分析用的部署，沒填用 `Deployment` |
| `InsightDeployment` | 口味分析用的部署，沒填用 `Deployment` |
| `BenchmarkDeployments` | 開發用：`POST /api/dev/benchmark` 要比較的部署名稱清單 |

```json
"AzureOpenAI": {
  "BenchmarkDeployments": ["<部署名稱1>", "<部署名稱2>"]
}
```

比較方式：後端以 Development 環境啟動後，`curl -X POST http://localhost:5122/api/dev/benchmark`，約需數分鐘，回傳各部署的解析／挑店秒數與挑到的店。
